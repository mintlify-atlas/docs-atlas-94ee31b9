## Overview

CotizaClima is a standalone web application that runs entirely in the browser. It works in **demo mode** by default and can optionally connect to Firebase Realtime Database for:

- Equipment catalog synchronization
- Quote history storage
- Client database management
- Usage analytics and rankings

## Quick Start (Demo Mode)

The fastest way to test CotizaClima:

<Steps>
  <Step title="Download Source Files">
    Copy all files from the `/source` directory to your web server or local folder:
    
    ```bash
    source/
    ├── index.html              # Main application
    ├── app.js                  # Core logic
    ├── firebase-auth.js        # Authentication service
    ├── quotes-repo.js          # Quote persistence

    ├── ranking-repo.js         # Analytics
    ```

## Firebase Configuration

To enable cloud features, configure Firebase Realtime Database connection.

### Prerequisites

<Steps>
  <Step title="Create Firebase Project">
    1. Go to [Firebase Console](https://console.firebase.google.com/)
    2. Click **"Add project"** or select existing project
    3. Enable **Realtime Database** from the Build menu
    4. Choose a database location (e.g., `us-central1`)
  </Step>

  <Step title="Configure Database Rules">
    Set read/write permissions in Firebase Console:
    
    <Tabs>
      <Tab title="Public Read (Recommended for testing)">
        ```json Database Rules
        {
          "rules": {
            "air_conditioners": {
              ".read": true,
              ".write": false
            },
            "accessories": {
              ".read": true,
              ".write": false
            },
            "quotes": {
              ".read": "auth != null",
              ".write": "auth != null"
            },
            "clients": {
              ".read": "auth != null",
              ".write": "auth != null"
            },
            "rankings": {
              ".read": "auth != null",
              ".write": "auth != null"
            }
          }
        }
        ```
        
        This allows:
        - Public read access to equipment and accessories
        - Authenticated access for quotes, clients, rankings
      </Tab>

      <Tab title="Authenticated Read (Production)">
        ```json Database Rules
        {
          "rules": {
            ".read": "auth != null",
            ".write": "auth != null"
          }
        }
        ```
        
        Requires authentication for all data access.
      </Tab>
    </Tabs>
  </Step>

  <Step title="Get Database URL">
    Copy your Firebase Realtime Database URL:
    
    ```
    Format: https://YOUR-PROJECT-ID-default-rtdb.firebaseio.com/
    Example: https://cotizaciones-app-ece65-default-rtdb.firebaseio.com/
    ```
    
    Found in: **Firebase Console → Realtime Database → Data tab (top of page)**
  </Step>
</Steps>

### Configure Connection in Code

Edit the `FIREBASE_CONNECTION` object in `app.js`:

```javascript app.js (lines 64-68)
const FIREBASE_CONNECTION = {
  databaseURL: 'https://YOUR-PROJECT-ID-default-rtdb.firebaseio.com/', 
  node: 'air_conditioners',  // Root node for equipment data
  authToken: ''              // Optional: database secret for server-side
};
```

<ParamField path="databaseURL" type="string" required>
  Your Firebase Realtime Database URL. Leave empty for demo mode.
  
  **Example**: `https://cotizaciones-app-ece65-default-rtdb.firebaseio.com/`
</ParamField>

<ParamField path="node" type="string" default="air_conditioners">
  Database node containing the equipment array.
  
  **Default**: `air_conditioners`
</ParamField>

<ParamField path="authToken" type="string">
  Optional database secret for authenticated REST API access. 
  
  **Note**: Only needed if database rules require authentication for reads.
</ParamField>

### How Connection Works

<CodeGroup>
```javascript Initialization Logic (app.js:160-186)
async function init() {
  try { await generateQuoteNumber(); } catch(e) {}
  try { renderAccGrid(); } catch(e) {}
  try { renderServiceGrid(); } catch(e) {}
  try { updateMultiServiceInputs(); } catch(e) {}
  try { updateStep2NextButton(); } catch(e) {}

  // Prioritize Firebase connection defined in code
  const activeUrl = FIREBASE_CONNECTION.databaseURL;
  const activeNode = FIREBASE_CONNECTION.node || 'air_conditioners';
  const activeToken = FIREBASE_CONNECTION.authToken || '';

  if (activeUrl) {
    // Load equipment and accessories in parallel from Firebase
    await Promise.all([
      loadFromFirebase(activeUrl, activeNode, activeToken),
      loadAccessoriesFromFirebase(activeUrl, activeToken)
    ]);
  } else {
    loadDemoData();
    showFirebaseStatus('error', 'Sin Firebase configurado — usando datos demo');
  }

  window.__cotizAppReady = true;
  document.dispatchEvent(new CustomEvent('cotiz:app-ready'));
  updateSortBtn();
  loadRankings().then(() => { if (Object.keys(acRankings).length > 0) filterAC(); });
}
```

```javascript Firebase Data Loading (app.js:237-272)
async function loadFromFirebase(url, node, authToken = '') {
  const cleanUrl = url.replace(/\/$/, ''); // Remove trailing slash
  const endpoint = buildFirebaseEndpoint(cleanUrl, node, authToken);

  try {
    showFirebaseStatus('connecting');
    const res = await fetch(endpoint);

    if (!res.ok) throw new Error(`HTTP ${res.status} — verifica la URL y las reglas de lectura`);

    const raw = await res.json();

    if (!raw) throw new Error('El nodo está vacío en Firebase');

    // Firebase stores arrays as numeric objects {0:{...}, 1:{...}}
    // This function normalizes them back to arrays
    const data = normalizeFirebaseArrays(raw);

    if (!Array.isArray(data) || data.length === 0) {
      throw new Error('No se encontraron equipos en el nodo indicado');
    }

    allAC = data;
    filteredAC = [...allAC];
    renderBrandFilterOptions();
    renderACGrid();
    updateStep1NextButton();
    showFirebaseStatus('ok', `${data.length} equipos cargados desde Firebase`);
    showToast(`${data.length} equipos actualizados`, 'success');

  } catch(e) {
    showFirebaseStatus('error', e.message);
    showToast('Firebase: usando datos demo', 'error');
    if (!Array.isArray(allAC) || allAC.length === 0) loadDemoData();
  }
}
```
</CodeGroup>

**Connection behavior:**

1. **If `databaseURL` is set**: Attempts to load from Firebase
   - Success: Equipment catalog synced from cloud
   - Failure: Falls back to demo data

2. **If `databaseURL` is empty**: Uses demo data immediately
   - Status indicator shows "Sin conexión Firebase"
   - All features work with built-in sample equipment

<Warning>
  The app **gracefully degrades** to demo mode if Firebase connection fails. Users can always create quotes, even without cloud connectivity.
</Warning>

### Session Management

Authentication uses Firebase REST API with automatic token refresh:

```javascript firebase-auth.js (lines 129-149)
async function getValidIdToken() {
  const session = readSession();
  if (!session || !session.idToken) return null;

  const nowSec = Math.floor(Date.now() / 1000);
  if (session.expiresAt && session.expiresAt > nowSec) {
    return session.idToken;  // Token still valid
  }

  if (!session.refreshToken) {
    clearSession();
    return null;
  }

  try {
    return await refreshIdToken(session.refreshToken);
  } catch (e) {
    clearSession();
    return null;
  }
}
```

- **Session storage**: User session persists until browser tab closes
- **Token refresh**: Automatic before expiration (every ~55 minutes)
- **Graceful logout**: Failed refresh clears session

## Troubleshooting

<AccordionGroup>
  <Accordion title="Red status dot - Firebase not connecting">
    **Possible causes:**
    - Incorrect `databaseURL` in `FIREBASE_CONNECTION`
    - Database rules deny read access
    - Network connectivity issue
    - Firebase project deleted/disabled

    **Solution:**
    1. Check console for error messages
    2. Verify database URL format (must end with `/`)
    3. Test database URL in browser (should return JSON)
    4. Review Firebase database rules
  </Accordion>

  <Accordion title="Equipment not loading">
    **Check:**
    - Data exists at `/air_conditioners` node in Firebase
    - Data is an array (or object with numeric keys)
    - Each equipment has required fields (marca, brand_model, capacities)
    - Database rules allow read access

    **Solution:**
    ```javascript
    // Test endpoint directly:
    fetch('https://YOUR-PROJECT.firebaseio.com/air_conditioners.json')
      .then(r => r.json())
      .then(data => console.log(data));
    ```
  </Accordion>

  <Accordion title="Login fails">
    **Check:**
    - `FIREBASE_AUTH_CONFIG.apiKey` is correct
    - Email/Password authentication enabled in Firebase
    - User account exists in Firebase Authentication
    - Credentials are correct

    **Error messages:**
    - `EMAIL_NOT_FOUND`: User doesn't exist
    - `INVALID_PASSWORD`: Wrong password
    - `USER_DISABLED`: Account disabled
    - `TOO_MANY_ATTEMPTS`: Too many failed logins, wait 1 hour
  </Accordion>

  <Accordion title="PDF generation fails">
    **Causes:**
    - jsPDF library not loaded
    - Browser blocked popup/download
    - Client data incomplete (missing required fields)

    **Solution:**
    - Check browser console for errors
    - Ensure name and address are filled
    - Try different browser
    - Check that jsPDF CDN is accessible
  </Accordion>

  <Accordion title="GPS button not working">
    **Requirements:**
    - HTTPS connection (not HTTP)
    - User grants location permission
    - Device has GPS/location services enabled

    **Solution:**
    - Use HTTPS in production (HTTP blocks geolocation)
    - Check browser permission settings
    - Test on device with location services on
  </Accordion>
</AccordionGroup>
